# ADR-011 — Economic result identity and retrospective outcomes
Status: P1-A engineering acceptance contract.

Replay inputs bind the complete execution fixture (cash, sessions, marks and retrospective path), and check it against the account/calendar projections before any ledger mutation. Source projections are read back from the actual snapshot closure; the reference feature is derived from its last-close input, not a self-declared hash. Replay inputs bind snapshot data/closure, feature version/hash, synthetic account hash, cost/rule/calendar/security versions and an actual 40-character implementation commit. Economic projections include versions, deterministic sequence, fills, integer ledger, daily NAV, cost attribution and path outcomes. Runtime UUID, trace and wall clock belong to audit only. Changes to a cost/rule version change the result identity even when rates or behavior remain the same. Mutation of snapshot bytes invalidates previous result/approval bindings.

MAE/MFE are retrospective outputs, never decision features. Horizons count explicit trading sessions. Daily high/low are labeled DAILY_APPROXIMATION. Intraday unknown entries exclude the entry day's range; entry at session open permits it. An absent expected session ends the continuous path; incomplete horizons are null. Days to positive use close above entry price before fees; time to MFE is the first strict new maximum high over entry; duration is longest consecutive closes below running peak, underwater days below entry. These are synthetic outcome conventions, not minute-level observations.

Per-execution gross rounding is summed from actual cumulative order results. It is never replaced with a whole-order rounded notional in attribution. The code byte map includes implementation, schemas, migrations, scripts and acceptance tests; a test or implementation change before release requires a new reviewed commit/pin.
