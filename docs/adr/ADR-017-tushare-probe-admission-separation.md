# ADR-017 — Tushare diagnostics, source identity and admission boundaries

Status: ACCEPTED for the human's bounded verification phase, 2026-10-05, including the latest monthly-gateway transport/rotation steering. This does not accept any data license, future policy or Research Pilot.

New diagnostic code lives under `tushare-admission/`, diagnostic contracts under `contracts/tushare-admission/`, and results under `docs/tushare-admission/`. Preserve the existing releases, 203 pinned source files, SQL001–006, SSE admission, legacy experiments and all previous reports. No database migration or durable live authority is introduced.

The compatible IP endpoint, the official provider, and the purchased product are separate identities. Owner's 15,000 tier is recorded with OWNER_ASSERTED provenance. Technical access may be established by a real scoped response; actual monthly term/expiry, operator identity, product binding, permitted purpose and storage/retention still need independent evidence. A public quota table is not an account record. Generic official terms are not evidence that a compatible proxy has an authorized resale/data relationship.

Old credential is prohibited; only Owner's newly obtained credential may be used. Supplier-provided formal HTTPS evidence (or documented HTTP-only with a later explicit Owner local exception) must precede credential lookup/send. Current public lookup and transport do not access storage/network; no dormant live HTTP sender is kept. Future activation needs a newly reviewed code epoch and the required source facts, within the existing limited authorization. No guessed HTTPS, TLS bypass, secret-store search, chat lookup, SDK default token file, token digest, secret-bearing diagnostic URL or redirect/fallback. Provider errors become enumerated reasons; direct and encoded secret echoes are discarded before body hashes or report persistence. Injected metadata clocks cannot persist arbitrary text.

Probe results are diagnostics, not SourceObservation2.0 or AdmissionReceipt2.0. Those frozen contracts support the previous SSE reference projection and terms basis; do not insert market/financial values or Tushare rights into them. Evidence and clock lineage remain `NOT_ISSUED` when actual retrieval or license proof is missing. Extending actual observation/policy/receipt contracts requires separately reviewed versioned extensions once an actual source/product/purpose can be bound. Never sign an unverified policy to create apparent permission.

Only documented symbol/date/quarter filters are used. Responses that ignore scope or limits fail validation. A zero-row response proves neither security safety nor history completeness. Raw daily and versioned adjustment factors are independent products; no adjusted-to-raw fallback. Decimal parsing and explicit provider-native units preserve precision without implying unit certification by the proxy. Revision flags/dates are retained as observed metadata and never prove availability at a historical cutoff.

Until retention terms are confirmed, the diagnostic runner stores only response shape/count/hash and clock metadata, not original market rows or credentials. This hash-only result is explicitly NOT_REPLAYABLE_RAW_EVIDENCE and cannot close a raw-original or financial-revision condition. Real original capture/storage requires source-specific permitted retention and a new exact policy. Current-observed availability can only equal actual successful retrieval; event and publication instants unknown remain null.

All purpose gates remain blocked and no existing C12–C22 condition closes automatically. Probe success cannot create Snapshot B; a real B requires genuinely new post-holiday data and admitted source/clock/version lineage. Public permissions and product manuals inform the probe plan; they do not authorize a trade, model call, redistribution or extra purchase. Stop after independent review of this bounded result.
