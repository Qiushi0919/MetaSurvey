# Historical PIT audit metadata 1.0.0

These three draft-07 schemas are closed, required-field metadata contracts. They do not modify the sixteen native V1 contracts, grant historical admission, or create ResearchCard/Signal/Approval/OrderIntent. The namespace is `HISTORICAL_PIT_PREPARATION:CORE_40`; the three engineering symbols are fixed. EVENT_3 and RESEARCH_6_18M cannot enter this path.

| Contract | Meaning | Invalidation / blocking |
| --- | --- | --- |
| HistoricalPITCandidateSnapshot | One observed logical date, optional NULL decision_time, no selected records until independent actual historical proof exists | Missing cutoff; unknown clocks/units/revisions; future metadata; caller-supplied admission; changed hash; wrong security/date/namespace |
| HistoricalPITClosureMatrix | Exact 20-domain × 3-security audit rows, preserve the previous map and required-field dictionary | Replaced baseline original; unproven first visibility/effective intervals; partial evidence; self-declared continuous closure; absent independent actual review |
| HistoricalBacktestPrerequisiteAttempt | Conditional Owner protocol plus BLOCKED_BEFORE_ENGINE and NULL trade metrics | Any prerequisite unresolved; fewer than1260 valid sessions; unreviewed anchor/label boundaries; exposed samples; actual cost/capital/slippage/risk/benchmark UNSET |

Every property is required; optional absence is explicit NULL where permitted. Exact enum/const states and hash syntax are in `contracts/historical-pit/*-v1.schema.json`. Schema checks are display/structure checks, never authority. Exact60 unique pairs, correct per-row original provenance, same Shanghai date, frozen spec hash and snapshot semantic hash require code-level verification, beyond JSON Schema. A caller's explicit time input is not an Owner attestation. Current metadata version has no actual proof issuer and cannot promote to ADMITTED; future positive integration needs separately reviewed evidence and contracts, not a boolean toggle.

`logical_session_date` is an observed raw-bar date, not an assertion that a complete historical exchange calendar passed. `decision_time` is NULL while UNSET_REQUIRED, otherwise an offset-aware Asia/Shanghai instant normalized to +08:00. Literal capture clocks in audit originals retain UTC offsets. Publication/event dates remain DATE_ONLY; a website date or today's retrieval cannot become historical midnight or first-visible time. `current_available_at`, `historical_available_at`, `first_visible_at`, `retrieved_at` are separate. Current financial/reporting/event dates are not a substitute for first usability. Content hashes are not vendor revision IDs; revision chains remain NOT_PROVEN.

The external audit inventory binds actual API, original response SHA-256, request fingerprint/alias, row ordinal and lexical raw values. Raw bars and adjustment factors remain separate API rows; no adjusted-price calculation or raw replacement occurs. Source units are preserved as unadmitted declarations; no money calculation uses them. Future/unproven audit records and their IDs/counts/hashes are excluded from each per-cutoff decision payload. The external audit inventory may retain rejected records for investigation.

Money rules remain ADR-003 / existing integer-cent and Decimal rules. No binary-float money, guessed rounding or historical experiment capital/commission is promoted. A blocked attempt has NULL gross/net/fee/slippage/turnover/MDD/excess/MAE/MFE and an empty PENDING ledger, not a zero-return backtest. Existing synthetic execution tests remain explicitly synthetic. Published fee schedules do not resolve actual dated broker/account inclusions, minimum commission, dividend tax, capital, risk or slippage.

Reason codes are frozen enumerations in each schema; the closure matrix keeps historical baseline reasons in a separate field. The new direct Owner authorization is conditional, recorded separately from those prior baseline reasons. New dated calendar documents are structural evidence only: planned annual holiday closures do not prove actual exceptional closures, complete trading sessions, individual security status or historical first visibility.

Verification: `node historical_pit/check.mjs` using the configured bundled Node and Python runtimes and unmoved private evidence paths. It performs no credential lookup, market request, signature, ledger append or engine call. Actual historical execution is not available through this entry.
